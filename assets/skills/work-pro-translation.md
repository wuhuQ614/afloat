# 专业翻译

不是「翻译这句话」，而是交付能直接用于求职/投稿/签约的译文。

## 触发时机

- 「把这份文档翻译成英文/中文」「帮我翻译简历/论文摘要/合同」「中英互译」（材料超过几段时）
- 单句短句翻译不必启用本技能，直接回答即可

## 工作流

### 1. 明确任务
用 `ask_user_question` 补齐关键项（一次问完）：
- 用途：投稿 / 求职 / 合同 / 宣发（决定正式度与风格）
- 术语偏好：行业术语是保留英文还是译出；机构名/产品名是否有官方译法
- 交付格式：双语对照 / 纯译文；md / docx（docx 走 work-office-docs）

### 2. 建术语表 `glossary.md`
通读原文（`read_file`），提取 10-30 个高频专业词/专有名词，确定统一译法。长文先派 `spawn_subagent`(`type=coder`) 或分段处理，术语表保证全文一致。

### 3. 初译 → 意译 → 校对（三道工序，不许合并）
1. **初译**：忠实原意，逐段直译，标记拿不准的句子；
2. **润色**：脱离原文读译文，改掉翻译腔——拆长句、调语序、换地道搭配；
3. **校对**：数字、日期、金额、单位、姓名逐项核对原文；术语表一致性检查。

### 4. 产出 `translation_<源>2<目标>.md`
```markdown
| 原文 | 译文 |
|------|------|
| ... | ... |

## 译注（可选）
- <术语取舍、文化适配的说明>
```
纯译文需求则只输出译文正文。

## 质量标准

- **简历**：动词开头（Led/Built/Delivered）、量化成果、无第一人称代词、美式或英式拼写全文一致
- **论文摘要**：被动语态适度、术语与领域惯例一致、不增删任何技术断言
- **合同**：条款编号一一对应；shall/may 权利义务色彩不改动；金额大小写保留双写
- **宣发文案**：允许创译（transcreation）——保效果不保字面，但事实性承诺不得走样
- 拿不准的地方宁可加「译注」向用户说明，不许静默糊弄过去

## 长文分片规则

超过 3000 字：按章节切分，每片独立走三道工序后拼接，最后做一遍全文术语一致性与行文连贯性终校。
