# 周报日报助手

把「这周干了啥」的流水账，变成领导 30 秒能看懂、突出价值与进度的汇报。

## 触发时机

- 「帮我写周报 / 日报 / 月报」「工作总结怎么写」「把这周的活儿汇总一下」

## 工作流

1. **收集素材**（按可用性依次尝试）：
   - 用户粘贴的零散记录
   - `session_query`(`list_sessions` → `search_history`) 检索本周与 AI 的协作记录里提到的工作内容
   - 工作区里的工作日志文件：先 `list_dir` 找 notes/log/todo 类文件，再 `read_file`
2. **素材不够就问**：用 `ask_user_question` 问关键缺口（本周最重要的 3 件事？有没有可量化的数字？下周计划？），一次问完。
3. **按结构产出**，写入 `weekly_report_<YYYY-Wnn>.md` 并在回复中给出全文。
4. 需要发邮件给领导 → 接 work-email-draft；需要 Word/PPT 版 → 接 work-office-docs。

## 周报结构

```markdown
# 周报：<姓名> · <YYYY-MM-DD ~ MM-DD>

## 本周核心进展（3-5 条，按重要性排序）
- 【完成】<事项>：<量化结果>（如 完成率 100%、转化率 +2.3%、提前 2 天）
- 【推进中】<事项>：当前进度 x%，预计 <时间> 完成
- 【风险/受阻】<事项>：卡点是什么，需要谁支持

## 数据看板（可选）
| 指标 | 本周 | 上周 | 环比 |
|------|------|------|------|

## 下周计划（不超过 5 条）
1. <事项> —— 目标/交付物

## 需要的支持与协调
```

## 写作规则

- **成果导向**：写「完成了什么、带来什么变化」，不写「做了什么动作」。
- **能量化就量化**：「优化了查询」→「查询耗时从 3.2s 降到 0.8s」；没有精确数字用区间或倍数，禁止编造精确数据。
- **坏消息不藏**：风险与求助单独成段，附上你已尝试的措施——这是加分项不是减分项。
- **动词开头、删形容词**：不用「很好地」「基本上」，直接陈述事实与数字。
- 篇幅 ≤500 字（用户明确要详细版除外）。

## 质量自检

提交前自查：领导只读「本周核心进展」一段，能否知道你干了什么、干成了什么、有什么风险？若不能，重写。
