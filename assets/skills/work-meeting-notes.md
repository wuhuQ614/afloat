# 会议纪要整理

把杂乱的原始素材变成一份可以归档、可以追责的结构化纪要。

## 触发时机

- 「帮我把这些速记整理成会议纪要」「写个 meeting minutes」
- 用户粘贴录音转写文字、群聊记录、自己潦草的要点
- 开完会口头描述，要求形成书面记录

## 工作流

1. **接收素材**：用户直接粘贴 → 若在文件里用 `read_file` 读取；素材太长（>8000 字）时分段读取或派 `spawn_subagent` 先做要点提取。
2. **信息不足先问**：日期、参会人、会议主题缺失时用 `ask_user_question` 补齐；用户说「你看着补」才允许标注（未确认）。
3. **按下方结构产出纪要**，写入 `meeting_notes_<YYYYMMDD>.md`。
4. **交付**：回复中给出纪要全文 + 文件路径；需要 Word 版走 work-office-docs 技能。

## 纪要结构

```markdown
# 会议纪要：<主题>

- 时间：<YYYY-MM-DD HH:mm>
- 地点/方式：
- 主持：
- 参会：（缺席单列）
- 记录：

## 一、议题与讨论
### 议题 1：<名称>
- 背景一句
- 主要观点：谁 · 说了什么核心论点（分歧要如实并列）
- **结论/决议**：

## 二、行动项（Action Items）
| # | 行动 | 负责人 | 截止时间 | 验收标准 |
|---|------|--------|----------|----------|
| 1 |      |        |          |          |

## 三、遗留问题 / 待下次讨论
## 四、附件与其他材料
```

## 整理规则

- **忠实优先**：只重组不编造。原话含糊处写「（待确认）」，禁止脑补决议。
- **口语→书面**：删语气词、重复、跑题；保留数字、日期、金额、型号等硬信息原样。
- **观点署名**：「张三认为…李四担心…」，不写成无主语的「大家认为」。
- **行动项必须可验收**：没有负责人的行动项放进「遗留问题」，不要伪装成已分配。
- 冲突观点并存时用「方案 A（支持者）/ 方案 B（支持者）—— 待决策」呈现。

## 加分动作

- 整理完成后主动问用户是否需要：① 把行动项单独导出成 Excel 跟踪表（走 work-office-docs）② 给缺席同事生成一段 200 字摘要。
